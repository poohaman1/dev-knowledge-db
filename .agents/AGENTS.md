# 프로젝트 에이전트 커스텀 규칙 (Project-Scoped Rules)

본 `dev-knowledge-db` 프로젝트에서 활동하는 모든 Antigravity 에이전트는 다음의 8대 핵심 관리 규칙을 절대적으로 준수해야 합니다.

---

## 📌 8대 핵심 에이전트 관리 규칙

### 1. 무조건 한국어로 답변할 것
- **사고(Thought)와 사용자 응답**: 모든 추론, 사고 과정 및 사용자 안내 응답은 반드시 자연스러운 한국어로 작성합니다.
- **코드 및 주석**: 변수명이나 함수명 등 코드 식별자는 영문 관례를 따르되, 모든 코드 주석과 설명문은 친절한 한국어로 작성합니다.

### 2. 안전성 우선 (사전 동의 필수)
- **코드 보호**: 기존의 정상 작동하는 코드를 대폭 수정하거나, 기존 파일을 삭제하기 전에는 **반드시** 사용자에게 *"이렇게 변경해도 될까요?"*라고 구체적인 변경 사유와 위험도를 설명하고 명시적 승인을 얻은 후 진행합니다.

### 3. 단계별 계획(Planning) 수립
- **구현 계획 아티팩트 필수**: 복잡한 기능 개발이나 아키텍처 변경 작업을 시작하기 전, 반드시 Implementation Plan(구현 계획)을 마크다운 아티팩트로 명확히 정리하여 사용자에게 먼저 제시합니다.

### 4. 친절하고 충분한 코드 설명 (교육용)
- **눈높이 교육 설명**: 사용자는 전문 개발자가 아닌 코딩 초보자(교육자)입니다. 코드를 작성하거나 수정할 때 단순히 코드만 던져주지 말고, 각 로직이 어떤 역할을 하는지 한글 주석과 함께 초보자의 눈높이에서 아주 상세하게 설명합니다.

### 5. 코드 생략 절대 금지 (Copy & Paste 보장)
- **완전한 전체 코드 제공**: 초보자는 코드가 생략되면 어디에 붙여넣어야 할지 모릅니다. 코드를 출력할 때 `// ... 기존 코드 ...`, `/* 생략 */` 등의 형태로 생략하지 말고, 바로 복사해서 덮어쓸 수 있도록 수정된 완전한 전체 코드를 제공합니다.

### 6. 단계별 진행 (Step-by-Step)
- **점진적 완성**: 한 번에 너무 많은 파일이나 복잡한 기능을 한꺼번에 수정하지 않습니다. 반드시 하나의 기능이 완벽하게 작동하는지 검증하고 사용자에게 확인받은 후 다음 단계로 넘어갑니다.

### 7. Supabase 쿼리 관리 규칙
- **순서 번호 명명 규칙**: 모든 SQL 쿼리 파일은 생성 시 파일명 앞에 `000_` 형태의 순서 번호를 반드시 붙여서 생성합니다 (예: `001_create_users_table.sql`, `002_add_encryption_columns.sql`).
- **전용 폴더 집중 관리**: 생성된 모든 쿼리 파일은 프로젝트 내에 흩어지지 않게 반드시 쿼리 전용 폴더(`supabase/migrations/`) 안에 모아서 체계적으로 정리합니다.

### 8. 강력한 보안 및 암호화 (최우선 과제)
- **보안 최우선 원칙**: 개발 시 보안을 최우선으로 고려합니다.
- **데이터베이스 전송 및 저장 전 필수 암호화**: 사용자의 개인정보나 민감한 데이터(학생 정보, 비밀번호, 주민등록번호, 연락처 등)를 다룰 때는 데이터베이스로 전달 및 저장하기 전에 반드시 강력한 암호화 로직(AES-256-GCM 양방향 암호화, Argon2id/bcrypt 단방향 해싱)을 적용합니다.
- **외부 해킹 및 역공학 방지(Anti-Reverse Engineering)**: 클라이언트 사이드 비밀키 노출 방지(BFF 아키텍처), 코드 난독화, 입력값 철저한 검증(SQL Injection/XSS 방어), 무결성 검증을 최적화합니다.
