# 🗄️ 데이터베이스(DB) 정보 및 선택 가이드

데이터베이스(Database)는 현대 애플리케이션의 심장입니다. 알맞은 데이터베이스를 선택하는 것은 시스템의 성능, 확장성, 그리고 비용을 결정짓는 가장 중요한 아키텍처 결정 중 하나입니다.

---

## 1. 관계형 데이터베이스 (RDBMS)

데이터를 엄격한 표(Table) 형태로 저장하며, 데이터의 무결성(ACID) 보장이 최우선인 시스템에 적합합니다.

### 🐬 MySQL / MariaDB

> **전 세계에서 가장 많이 사용되는 오픈소스 RDBMS.** 가볍고 빠르며 생태계가 압도적입니다.

- **🎯 추천 대상:** 일반적인 웹 서비스, 쇼핑몰, 블로그 등 범용 목적
- **💡 전문가 팁:** 복잡한 쿼리 최적화나 수평적 확장(Scale-out)에는 한계가 있으나, Read-Heavy 트래픽에는 Replication 구조로 탁월한 가성비를 자랑합니다.

### 🐘 PostgreSQL

> **오픈소스계의 오라클.** 오픈소스 RDBMS 중 가장 진보된 기능을 제공합니다.

- **🎯 추천 대상:** 복잡한 쿼리 연산, 공간 데이터(PostGIS), JSON 데이터 처리가 혼합된 하이브리드 워크로드
- **💡 전문가 팁:** 동시성 제어(MVCC)가 뛰어나며, 복잡한 JOIN과 분석 쿼리 성능이 MySQL보다 우수합니다. 스타트업 및 엔터프라이즈 메인 DB로 각광받고 있습니다.

### 🔴 Oracle Database

> **상용 RDBMS의 절대 강자.** 압도적인 성능과 안정성, 암호화, 백업 기능을 제공합니다.

- **🎯 추천 대상:** 금융권, 대기업 ERP, 절대로 멈추면 안 되는 미션 크리티컬 시스템
- **💡 전문가 팁:** 라이선스 비용이 매우 높으나, 대규모 트랜잭션 처리(RAC)와 PL/SQL 프로시저 처리에 있어 대체 불가능한 영역이 존재합니다.

## 2. NoSQL (비관계형 데이터베이스)

정해진 스키마(표 구조) 없이 유연하게 데이터를 저장하며, 대용량 트래픽에 대한 빠른 읽기/쓰기와 유연한 확장에 특화되어 있습니다.

### 🍃 MongoDB (Document DB)

> **유연한 JSON 문서 저장소.** 개발자가 다루는 데이터 객체를 그대로 넣고 뺄 수 있습니다.

- **🎯 추천 대상:** 스키마가 자주 변경되는 서비스, 빠른 프로토타이핑, 게임 로그 데이터 저장
- **💡 전문가 팁:** Sharding을 통한 수평 확장이 쉽습니다. 단, 정규화보다는 데이터의 중복 저장을 감수하는 비정규화(Denormalization) 설계가 필요합니다.

### ⚡ Redis (Key-Value DB / In-Memory)

> **초고속 메모리 DB.** 데이터를 RAM에 저장하여 마이크로초(µs) 단위의 응답 속도를 보여줍니다.

- **🎯 추천 대상:** 세션 관리, 랭킹 보드(Sorted Set), 캐싱(Caching), 실시간 대기열
- **💡 전문가 팁:** 주력 저장소로 쓰기엔 메모리 비용이 비쌉니다. 주로 메인 DB 앞단의 캐시 레이어(Cache Layer)로 활용되어 DB 부하를 낮춥니다.

### 👁️ Cassandra / DynamoDB (Wide-Column DB)

> **마스터 없는 무한 확장 DB.** 수백, 수천 대의 서버로 분산 저장하는 데 특화되어 있습니다.

- **🎯 추천 대상:** 글로벌 스케일 시계열 데이터, IoT 센서 데이터 수집, 초대규모 쓰기 트래픽
- **💡 전문가 팁:** 최종 일관성(Eventual Consistency)을 기본으로 하므로, 실시간 데이터 무결성이 중요한 결제 시스템에는 부적합합니다.

## 3. 최신 트렌드: NewSQL & Vector Database

클라우드 환경과 인공지능(AI) 시대의 요구사항에 맞춰 새롭게 등장한 패러다임입니다.

### 🌍 NewSQL (CockroachDB, TiDB)

> **NoSQL의 확장성과 RDBMS의 무결성을 결합한 꿈의 데이터베이스**

- **🎯 추천 대상:** 폭발적으로 성장하는 글로벌 서비스, 샤딩(Sharding) 관리로 고통받는 개발팀
- **💡 전문가 팁:** 내부적으로 분산 저장(KV)을 쓰면서 겉으로는 SQL을 지원합니다. 스토리지와 연산 계층이 분리된 클라우드 네이티브 구조입니다.

### 🧠 Vector Database (Pinecone, Milvus, Qdrant)

> **AI 시맨틱 검색 인프라.** 비정형 데이터를 고차원 벡터로 변환 저장하고 초고속으로 검색합니다.

- **🎯 추천 대상:** ChatGPT 기반 RAG 시스템, 추천 알고리즘, 이미지/음성 검색
- **💡 전문가 팁:** 일반 DB의 일치 검색이 아닌 근사 최근접 이웃(ANN) 탐색 알고리즘을 사용합니다. AI 챗봇 구현 시 필수적입니다.

## 🧭 개발자를 위한 선택 가이드

### 👶 초보 개발자 (주니어 & 토이 프로젝트)

::: tip 1. 어떤 DB를 써야 할지 전혀 모르겠다면?
👉 **PostgreSQL (또는 MySQL)**
관계형 모델링은 백엔드 개발자의 기본 소양입니다. 일단 관계형 DB로 뼈대를 잡으세요.
:::

::: tip 2. 게시판, 쇼핑몰, 블로그를 만든다면?
👉 **MySQL** 또는 **PostgreSQL**
:::

::: tip 3. 스키마 설계 없이 프론트엔드 위주로 출시하고 싶다면?
👉 **Firebase (Firestore)** 또는 **Supabase**
:::

::: tip 4. 단순 API 서버 캐싱을 경험해보고 싶다면?
👉 **Redis**
:::

### 👨‍💻 전문 개발자 (시니어 & 아키텍트 체크리스트)

(모바일 환경을 고려하여 질문을 탭하면 답변이 보입니다.)

::: details 💡 데이터 무결성(결제, 돈)이 최우선인가요? (ACID vs CAP)
**추천 DB 패턴:** `RDBMS` (PostgreSQL, Oracle), `NewSQL`
:::

::: details 💡 읽기 트래픽이 압도적으로 많나요?
**추천 DB 패턴:** `RDBMS` + `Redis` (캐시)
:::

::: details 💡 쓰기 트래픽이 단일 서버 한계를 넘었나요? (수평 확장)
**추천 DB 패턴:** `Cassandra`, `MongoDB`, 또는 `NewSQL` 도입 고려
:::

::: details 💡 스키마가 없고 필드가 동적으로 매우 자주 변하나요?
**추천 DB 패턴:** `MongoDB` (Document Store)
:::

::: details 💡 친구 추천 등 복잡한 네트워크 탐색 및 관계 추적이 필요한가요?
**추천 DB 패턴:** `Graph DB` (Neo4j)
:::

::: details 💡 문서 내용을 기반으로 한 AI 기반 의미 검색이 필요한가요?
**추천 DB 패턴:** `Vector DB` (Pinecone, Milvus)
:::

---

::: info 💡 **최종 조언 (Polyglot Persistence)**
"완벽한 단일 데이터베이스는 없습니다." 규모가 커진 현대의 마이크로서비스 아키텍처(MSA)에서는, 결제는 **PostgreSQL**, 유저 로그는 **MongoDB**, 캐싱은 **Redis**, 검색은 **ElasticSearch**를 사용하는 다국어 영속성 구조가 필수적입니다. 각 DB의 한계점(Trade-off)을 명확히 이해하고 적재적소에 조합하는 것이 핵심입니다.
:::
