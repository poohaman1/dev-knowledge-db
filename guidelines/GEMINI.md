# Gemini 보조 활용 가이드 (GEMINI.md)

이 문서는 구글의 Gemini 모델을 Antigravity 개발 환경의 보조자(Assistant)로 활용할 때, 웹(Web)과 앱(App) 환경에 최적화된 프롬프트 템플릿과 활용법을 안내합니다.

---

## 1. 🌐 웹 환경 특화 프롬프트

웹 개발 시 CSS 충돌, 브라우저 디버깅, DOM 분석 등을 Gemini에게 요청할 때 효과적인 프롬프트입니다.

### 1.1 브라우저 에러 및 네트워크 분석
```text
당신은 브라우저 렌더링 엔진과 네트워크 프로토콜에 정통한 웹 프론트엔드/백엔드 전문가입니다.
다음 브라우저 개발자 도구(Console/Network 탭) 에러 로그를 분석해 주세요.

[요구사항]
1. CORS 에러, 404/500 HTTP 상태 코드, 또는 렌더링 오류의 구체적 원인 3가지 도출
2. 프론트엔드 코드(React/Vue 등) 관점에서의 수정 방안
3. 백엔드(Node.js/Spring 등) API 응답 헤더 관점에서의 해결책
```

### 1.2 반응형 및 UI 최적화
```text
다음은 특정 컴포넌트의 HTML과 CSS 코드입니다. 
모바일 및 데스크톱 환경에서 레이아웃이 깨지지 않도록 미디어 쿼리(Media Query) 또는 CSS Grid/Flexbox를 사용하여 리팩토링해 주세요.

[요구사항]
- 분기점: 모바일(768px 이하), 태블릿(768px~1024px), 데스크톱(1024px 이상)
- 변경된 CSS 코드와 이를 HTML에 적용한 예시 제공
```

## 2. 📱 모바일 환경 특화 프롬프트

모바일 앱 개발 시 디바이스 종속성 해결, 모바일 로그캣 분석, 플랫폼별 에러 대응을 Gemini에게 요청할 때 효과적입니다.

### 2.1 네이티브 로그(Logcat / Xcode Console) 분석
```text
당신은 Android와 iOS 네이티브 환경 및 모바일 하드웨어 딥다이브가 가능한 모바일 수석 개발자입니다.
다음 모바일 디바이스 로그(Logcat 또는 Xcode Console)를 분석해 주세요.

[요구사항]
1. NullPointerException, 뷰 계층 구조 에러, 혹은 메모리 누수(OOM)의 근본 원인 도출
2. (크로스플랫폼의 경우) 브릿지(Bridge) 통신 과정에서의 데이터 유실 여부 점검
3. 디버깅을 위해 추가로 심어야 할 로깅 코드와 네이티브(Java/Swift) 방어 코드 제시
```

### 2.2 앱 심사 리젝(Reject) 사유 분석 및 대응
```text
우리 앱이 [Apple App Store / Google Play Store] 심사에서 다음과 같은 사유로 리젝되었습니다.

[리젝 사유]
(리젝 메시지 첨부)

[요구사항]
1. 해당 스토어의 가이드라인 조항을 근거로 리젝 원인 해설
2. 앱 코드 내에서 수정해야 할 퍼미션(Permission) 요청 타이밍 및 UI/UX 변경 사항 제안
3. 스토어 리뷰어에게 제출할 영문 해명(소명) 메시지 초안 작성
```

## 3. 프롬프트 개선기 (웹/앱 공통)

내가 작성한 프롬프트를 더 고품질로 튜닝하고자 할 때 사용합니다.

```text
나는 특정 (웹/앱) 기능을 개발하기 위한 프롬프트를 작성했습니다. 
LLM이 나의 의도를 완벽히 이해하고, 실제 운영 서버/스토어에 배포 가능한 수준의 코드를 낼 수 있도록 프롬프트를 개선해 주세요.

[내가 작성한 프롬프트]
"(내용)"

[개선 방향]
- 모바일 제약이나 브라우저 제약을 고려한 구체적 지시어 추가
- 출력 형태(마크다운, JSON 구조 등) 명확화
```
